# 个人资产管理系统一期设计

## 1. 背景与目标

本系统用于练习 GoFrame 后端开发，第一期只实现后端 API，不实现前端页面。

一期目标是完成一个标准 CRUD 后台接口雏形，并在资产模块中加入少量业务动作，练习 GoFrame 的接口定义、控制器、Service、Logic、DAO、事务、参数校验和 MySQL 数据建模。

## 2. 一期范围

一期包含以下能力：

- 建筑、楼层、房间三层位置维度管理。
- 分类、产品、资产三层资产维度管理。
- 资产支持手动编码和自动编码。
- 资产支持入库和位置转移。
- 资产表保存当前位置。
- 位置变更写入资产位置记录表。
- 基础资料删除时做引用保护。

一期不包含以下能力：

- 前端页面。
- 登录、权限、菜单。
- 采购、领用、借用、归还。
- 盘点、维修、报废流程。
- 图片、附件、二维码。
- 多租户或多人协作。

## 3. 技术选型

- 后端框架：GoFrame。
- 数据库：MySQL。
- 接口形态：REST 风格后端 API。
- 数据访问：优先使用 `gf gen dao` 生成 DAO、Entity、DO。
- 事务边界：资产入库、资产转移、自动编码新增资产。

## 4. 模块设计

### 4.1 位置模块

位置由建筑、楼层、房间三层组成。

```text
building -> floor -> room
```

建筑用于表示一个大地点，例如家、办公室、仓库。

楼层隶属于建筑。

房间隶属于楼层，同时冗余保存 `building_id`，方便查询和校验。

### 4.2 产品模块

产品由分类和产品组成。

```text
category -> product
```

分类支持树形结构，第一期只要求能通过 `parent_id` 建立父子关系，不强制实现复杂树查询。

产品隶属于分类，用于定义资产实例的通用信息，例如品牌、型号、单位。

### 4.3 资产模块

资产实例隶属于产品。

```text
product -> asset_item
```

资产实例表示具体的一件资产，例如某一台笔记本电脑。

资产表保存当前位置：

```text
asset_item.current_building_id
asset_item.current_floor_id
asset_item.current_room_id
```

资产位置记录表保存入库和转移记录。

```text
asset_item -> asset_location_record
```

## 5. 数据表设计

### 5.1 asset_building

```text
id
name
code
address
remark
created_at
updated_at
deleted_at
```

约束：

- `code` 唯一。
- `name` 必填。

### 5.2 asset_floor

```text
id
building_id
name
code
floor_no
remark
created_at
updated_at
deleted_at
```

约束：

- `building_id` 必填。
- `code` 唯一。
- `name` 必填。
- 删除建筑前，必须确认建筑下没有楼层。

### 5.3 asset_room

```text
id
building_id
floor_id
name
code
room_no
remark
created_at
updated_at
deleted_at
```

约束：

- `building_id` 必填。
- `floor_id` 必填。
- `code` 唯一。
- `name` 必填。
- `floor_id` 必须属于 `building_id`。
- 删除楼层前，必须确认楼层下没有房间。
- 删除房间前，必须确认房间未被资产引用。

### 5.4 asset_category

```text
id
parent_id
name
code
sort
remark
created_at
updated_at
deleted_at
```

约束：

- `parent_id` 默认为 0。
- `code` 唯一。
- `name` 必填。
- 删除分类前，必须确认分类下没有子分类和产品。

### 5.5 asset_product

```text
id
category_id
name
code
brand
model
unit
remark
created_at
updated_at
deleted_at
```

约束：

- `category_id` 必填。
- `code` 唯一。
- `name` 必填。
- 删除产品前，必须确认产品未被资产引用。

### 5.6 asset_item

```text
id
product_id
asset_code
name
status
current_building_id
current_floor_id
current_room_id
purchase_date
purchase_price
remark
created_at
updated_at
deleted_at
```

约束：

- `product_id` 必填。
- `asset_code` 唯一。
- `name` 必填。
- `status` 必填。
- 传入当前位置时，必须校验房间、楼层、建筑关系正确。

状态：

```text
1 = 闲置
2 = 在用
3 = 维修
4 = 报废
```

一期只强制实现闲置和在用，维修、报废作为枚举预留。

### 5.7 asset_location_record

```text
id
asset_id
action_type
from_building_id
from_floor_id
from_room_id
to_building_id
to_floor_id
to_room_id
operated_at
remark
created_at
```

约束：

- `asset_id` 必填。
- `action_type` 必填。
- 入库记录允许 `from_*` 为空。
- 转移记录要求 `from_*` 和 `to_*` 都存在。

动作类型：

```text
inbound = 入库
transfer = 转移
```

## 7. 核心业务规则

### 7.1 自动编码

资产编码支持手动传入和系统自动生成。

如果创建资产时传入 `asset_code`：

- 校验编码不能为空。
- 校验编码全局唯一。
- 直接使用该编码。

如果创建资产时未传入 `asset_code`：

- 根据产品编码和当天日期自动生成。
- 自动生成和资产保存必须在同一个事务中。

一期编码规则：

```text
ASSET-{产品code}-{yyyyMMdd}-{三位序号}
```

示例：

```text
ASSET-NOTEBOOK-20260624-001
```

序号按产品编码和日期递增。

### 7.2 新增资产

新增资产时必须选择产品。

如果传入房间：

- 校验房间存在。
- 校验房间所属楼层和建筑关系正确。
- 写入资产当前位置。
- 写入一条 `inbound` 位置记录。

如果不传入房间：

- 资产当前位置为空。
- 不写入位置记录。

### 7.3 资产入库

入库接口用于把未入库或需要重新入库的资产放入指定房间。

规则：

- 资产必须存在。
- 目标房间必须存在。
- 目标房间所属楼层和建筑关系必须正确。
- 更新资产当前位置。
- 写入 `inbound` 位置记录。
- 整个过程必须在事务中完成。

### 7.4 资产转移

转移接口用于把已有当前位置的资产移动到另一个房间。

规则：

- 资产必须存在。
- 资产必须已有当前位置。
- 目标房间必须存在。
- 目标房间不能等于当前位置。
- 更新资产当前位置。
- 写入 `transfer` 位置记录。
- 整个过程必须在事务中完成。

### 7.5 删除引用保护

删除基础资料时必须做引用保护。

规则：

- 建筑下存在楼层时，不允许删除建筑。
- 楼层下存在房间时，不允许删除楼层。
- 房间被资产引用时，不允许删除房间。
- 分类下存在子分类或产品时，不允许删除分类。
- 产品被资产引用时，不允许删除产品。

## 8. GoFrame 分层建议

建议使用以下结构：

```text
api/asset/v1
internal/controller/asset
internal/service
internal/logic/asset
internal/dao
internal/model
manifest/sql
```

职责：

- `api/asset/v1`：定义请求和响应结构。
- `internal/controller/asset`：处理 HTTP 入口，调用 service。
- `internal/service`：定义业务接口。
- `internal/logic/asset`：实现业务逻辑、事务、跨表校验。
- `internal/dao`：由 `gf gen dao` 生成。
- `internal/model`：承载内部输入输出结构。
- `manifest/sql`：保存建表 SQL。

## 9. 验证计划

一期至少验证以下场景：

- 建筑、楼层、房间 CRUD 正常。
- 分类、产品 CRUD 正常。
- 建筑、楼层、房间删除引用保护正确。
- 分类、产品删除引用保护正确。
- 手动资产编码新增成功。
- 重复资产编码新增失败。
- 自动资产编码新增成功。
- 新增资产时传入房间后，资产当前位置正确，且生成入库记录。
- 资产入库后，当前位置和入库记录正确。
- 资产转移后，当前位置和转移记录正确。
- 转移到相同房间时失败。
